# UX Requirements - Kai 容器管理

## 模組簡介

本模組提供使用者介面與核心邏輯，用於管理 Flexy 容器的完整生命週期，包括查看、建立、操作與存取。

---

## Requirements

### Requirement ID: KAI-01 (儀表板檢視)
- **對應 User Story**: story-kai-Dev-001
- **需求描述**: 使用者必須能夠看到所有 Flexy 容器的列表及其當前狀態。
- **互動細節**:
  - 載入主頁面時，系統自動擷取並顯示容器列表。
  - 列表以表格或卡片形式呈現。
  - 每個項目顯示：名稱、狀態、容器 ID、資料夾掛載路徑。
  - 提供「重新整理」按鈕以手動更新列表。
  - 提供搜尋/篩選欄位，讓使用者能依名稱快速尋找容器。
- **成功條件**:
  - 容器列表在 2 秒內載入並顯示。
  - 容器狀態準確反映實際情況。
  - 搜尋欄位能隨著使用者輸入即時篩選列表。
- **異常情境**:
  - 若後端 API 無法連線，顯示錯誤訊息：「無法連接到後端服務，請稍後再試。」
  - 若無任何容器，顯示提示訊息：「目前沒有任何 Flexy 容器，請點擊『新增 Flexy』來建立一個。」
- **銜接點**: User Flow - `ViewDashboard`

### Requirement ID: KAI-02 (容器操作)
- **對應 User Story**: story-kai-Dev-001, story-kai-Dev-003
- **需求描述**: 使用者能對列表中的單一容器執行操作（啟動、停止、刪除、進入 Shell）。
- **互動細節**:
  - 每個容器項目旁都有一組操作按鈕。
  - 「啟動/停止」按鈕會根據容器當前狀態顯示對應文字。
  - 點擊「刪除」按鈕時，彈出確認對話框，防止誤刪。
  - 點擊「進入 Shell」按鈕，頁面導航至該容器的 Shell 介面。
- **成功條件**:
  - 啟動/停止/刪除操作能在 5 秒內完成，並更新 UI 狀態。
  - 點擊「進入 Shell」後成功導航至對應的 Shell 頁面。
- **異常情境**:
  - 若操作失敗（例如 Docker Engine 錯誤），在 UI 上顯示清晰的錯誤通知。
- **銜接點**: User Flow - `OperateContainer`, `AccessShell`

### Requirement ID: KAI-03 (新增容器)
- **對應 User Story**: story-kai-Dev-002
- **需求描述**: 使用者能透過 UI 介面建立一個新的 Flexy 容器。
- **互動細節**:
  - 點擊儀表板上的「新增 Flexy」按鈕，彈出一個 Modal 視窗。
  - Modal 中包含「名稱」輸入框（必填）與「資料夾掛載」輸入框（可選）。
  - 「資料夾掛載」旁提供一個按鈕，可開啟主機目錄瀏覽器，方便使用者選擇路徑。
  - 點擊「建立」按鈕後，向後端發送請求，並在 UI 上顯示處理中的狀態。
- **成功條件**:
  - 成功建立容器後，Modal 關閉，儀表板列表自動刷新並顯示新建立的容器。
- **異常情境**:
  - 若輸入的名稱已存在或格式不符，顯示對應的欄位錯誤提示。
  - 若後端建立失敗，在 Modal 中顯示錯誤訊息，且 Modal 不會自動關閉。
- **銜接點**: User Flow - `CreateContainer`
