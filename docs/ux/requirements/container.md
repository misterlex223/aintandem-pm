# UX Requirements - Container Management

本模組的核心任務是提供一個完整的 Web 介面，讓使用者可以直觀地建立、管理、操作和存取 Flexy 容器。

---

## Requirements

### Requirement ID: CONTAINER-01
- **對應 User Story**: story-container-Dev-001
- **需求描述**: 使用者需要一個清晰的列表來查看所有已建立的 Flexy 容器及其關鍵資訊。
- **互動細節**:
  - **UI 元件**: 一個表格 (Table) 或卡片 (Card) 列表，用於展示所有容器。
  - **顯示欄位**: 必須包含容器名稱、狀態 (例如: running, stopped)、創建時間、資料夾掛載路徑。
  - **操作**: 頁面應提供一個手動刷新按鈕，以便在需要時立即更新列表。
- **成功條件**:
  - 頁面載入時，能成功從後端獲取並顯示所有容器的正確資訊。
  - 容器的狀態能準確反映其在 Docker 中的真實狀態。
- **異常情境**:
  - 若後端 API 無法連線或返回錯誤，應在列表區域顯示一個明確的錯誤提示，例如「無法獲取容器列表，請檢查後端服務狀態」。
- **銜接點**: `flow-container-view-list`

### Requirement ID: CONTAINER-02
- **對應 User Story**: story-container-Dev-002
- **需求描述**: 使用者需要透過 UI 介面快速建立一個新的 Flexy 容器。
- **互動細節**:
  - **UI 元件**: 一個「新增 Flexy」按鈕；一個彈出式視窗 (Modal) 作為建立表單；用於輸入「容器名稱」的輸入框 (Input)；用於輸入「Folder mapping」的文字區 (Textarea)。
  - **操作流程**: 使用者點擊「新增 Flexy」按鈕 -> 在 Modal 中填寫表單 -> 點擊「建立」按鈕提交。
  - **系統反饋**: 提交後，在按鈕上顯示 loading 狀態。建立成功後，Modal 自動關閉，容器列表自動刷新。若建立失敗，則在 Modal 內顯示具體的錯誤訊息。
- **成功條件**:
  - 新的容器成功被建立，並立即以 `running` 狀態出現在容器列表中。
- **異常情境**:
  - **容器名稱重複**: 提交時應提示「容器名稱已存在，請使用其他名稱」。
  - **Folder mapping 格式錯誤**: 提交時應提示「路徑格式不正確，請使用 /host/path:/container/path 格式」。
  - **後端建立失敗**: 應將後端返回的錯誤訊息顯示給使用者。
- **銜接點**: `flow-container-create`

### Requirement ID: CONTAINER-03
- **對應 User Story**: story-container-Dev-003
- **需求描述**: 使用者需要能夠在列表中直接啟動或停止一個已存在的容器。
- **互動細節**:
  - **UI 元件**: 位於容器列表每一項中的「啟動/停止」切換按鈕 (Button)。
  - **操作**: 使用者直接點擊該按鈕。
  - **系統反饋**: 按鈕點擊後短暫顯示 loading 狀態。操作成功後，按鈕的文字與容器的狀態指示應同步更新 (例如，從「啟動」變為「停止」，狀態從 `stopped` 變為 `running`)。
- **成功條件**:
  - 容器的實際狀態成功改變。
  - UI 上的狀態指示在 5 秒內完成更新。
- **異常情境**:
  - 若後端操作失敗，應彈出一個提示 (Toast) 告知使用者「操作失敗」，且 UI 狀態應恢復原狀。
- **銜接點**: `flow-container-manage-state`

### Requirement ID: CONTAINER-04
- **對應 User Story**: story-container-Dev-004
- **需求描述**: 使用者需要能夠刪除一個不再需要的容器，以釋放資源。
- **互動細節**:
  - **UI 元件**: 位於容器列表每一項中的「刪除」按鈕；一個確認對話框 (Alert Dialog)。
  - **操作流程**: 使用者點擊「刪除」按鈕 -> 系統彈出確認對話框 -> 使用者點擊「確認刪除」。
  - **系統反饋**: 點擊「刪除」後，在確認按鈕上顯示 loading 狀態。成功後，該容器項從列表中移除。
- **成功條件**:
  - 容器成功從後端被移除。
  - 該容器項從 UI 列表中消失。
- **異常情境**:
  - 若後端刪除失敗，應彈出提示告知使用者「刪除失敗」。
- **銜接點**: `flow-container-delete`

---

### Requirement ID: CONTAINER-05
- **對應 User Story**: story-container-Dev-005
- **需求描述**: 使用者需要一個快速入口，以便直接在瀏覽器中存取容器的 Shell。
- **互動細節**:
  - **UI 元件**: 位於狀態為 `running` 的容器項中的「進入 Shell」按鈕。
  - **操作**: 使用者點擊該按鈕。
  - **系統反饋**: 系統導航至一個新的頁面 (`/flexy/{id}/shell`)，該頁面內嵌了對應容器的終端機介面。
- **成功條件**:
  - 使用者能成功看到並操作一個功能完整的 Shell 終端機。
- **異常情境**:
  - **容器未運行**: 「進入 Shell」按鈕應為禁用狀態或不可見。
  - **代理連線失敗**: 若無法連接到 ttyd 服務，應在 Shell 頁面顯示錯誤訊息「無法連接到容器 Shell」。
- **銜接點**: `flow-container-access-shell`
